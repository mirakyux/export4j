# 工程笔记：矢量的原子来源与逻辑阅读文字分离

状态：已实现

## 先说结论

调用方已生成的公式轮廓通过不可变 `VectorResource`／`InlineVector` 接入语义段落及单元格。几何与逻辑阅读文字构成同一个原子值，原始来源只占一个 UTF-16 单元；不把多字符 TeX 的长度当作来源跨度，也不让模板仅改文字却复用旧轮廓。

## 问题

文献中的公式图片可以保留视觉，却无法仅靠图片替代文字获得 PDF 中的公式阅读原文。直接借用低层轮廓又容易漏掉模板、编辑、重放、表格预算和跨格式保存。尤其当一枚 U+FFFC 的轮廓包含多字符逻辑文字时，按阅读文字长度推进来源会使后续文字外链或来源范围错位。

图片混排也有独立边界：整行轮廓保留视觉及 ActualText，但忽略 ActualText 的普通提取器无法还原原生文字。修复来源不等于可以把复杂塑形结果直接按单字重新输出。

## 决策

- [模型 API](../../../../docs/inline-vectors-api.md) 使用自有有界段类型，无第三方或 AWT 句柄；快照、有限数值、子路径顺序、尺寸、段数和阅读文字在模型边界验证。资源 ID 包含尺寸与规范化坐标，规范字节预算不冒称实际堆大小。
- `Paragraph`／`TableCell` 保留所有旧构造器，新增矢量来源视图；`mixed` 统一生成原子标记、默认样式及外链。复制、模型压缩、模板和整体编辑保留同一资源；块单元格不通过旧视图隐藏后代。
- [TextOutline](../../../../export4j-text-core/src/main/java/com/mirakyux/export4j/text/TextOutline.java) 明确区分 `sourceLength` 与 `logicalText.length()`；旧文字构造器保持原长度，矢量原子消费 1。外链和后续来源使用前者，PDF ActualText 使用后者。
- 普通输入按唯一几何计源预算，重复绘制计呈现工作；流式输入按出现次数保守计几何，避免全流资源 ID 无界驻留。模板、编辑和页区另有各自工作预算。
- 变宽候选准备及重试也累计逻辑阅读文字和几何工作，不能只按一枚 marker 收费；在转换路径前按出现次数预检段数，避免先复制大轮廓再发现预算超限。单次转换可局部共享不可变路径，但不引入跨会话缓存。
- HTML／Markdown 只接受明确登记的资源键，不隐式解析 TeX／SVG或取网络资源。无对应语义的 Web／DOCX 出口默认失败，仅明确 DEGRADE 才保留逻辑文字并报告损失；XML v1 不伪造矢量恢复数据。
- 仅图片混排的安全 LTR、静态 TTF、一字一 GID、无装饰／字段／矢量行可复用既有塑形坐标发出原生字形。任一条件不满足则整行保留原轮廓；不改测量、不猜 Unicode、不抹去复杂塑形。底层编码继续遵循[原文／字形分离](../bug-fix/2026-11-12-pdf-unicode-glyph-aliases.md)。

## 考虑过的备选方案

- 一律将 TeX 光栅化：能保留视觉，但图片 alt 不等于 PDF 中保留原 TeX，不作为唯一合作入口。
- 把公式解析器和第三方公式类型放入核心 API：扩大依赖及执行预算边界；由调用方生成有界轮廓即可满足当前接入。
- 模板只插值 `logicalText`：会产生文字与图形不一致；动态公式须整体重建。
- 将全部图文混排改为逐字原生字体：会破坏连字、组合簇、双向及复杂脚本。采用可证明的一一映射子集，不能证明时保留原路径。
- Web／DOCX 静默转文字或 XML 静默丢资源：生成成功却损坏后续保存／恢复，改为明确策略或拒绝。

## 后果

高层接入不再依赖自定义组件，轮廓与原 TeX 可以一同保留；代价是额外原子来源及工作账本。公式仍是绘制资源，不是可编辑公式语义树；没有自动 TeX↔OMML、完整 LaTeX、通用 SVG 或跨格式无损恢复。ActualText、普通提取、搜索和选区仍需按独立工具分别验证。

FontBox 继续使用官方依赖，补丁构建选项已经完整移除，决定与生命周期理由见[有界文字与 PDF 复用](../simplification/2026-11-12-bounded-text-pdf-reuse.md)。新的文字表示不能据此宣称字体解析内存下降，也不以低质量图片或公式换取指标。

## 验证

- [InlineVectorTest](../../../../export4j-model/src/test/java/com/mirakyux/export4j/model/InlineVectorTest.java)覆盖防御快照、规范化身份、非法几何与原文、marker 冲突、模型复制、模板／编辑原子性及预算。
- 模型、布局、文字、流式重放、Web／DOCX／XML 的相关回归与本地构建通过；变宽长逻辑文字回归证明每次候选准备都计费，跨组流式回归证明全流预算不被分组重置。最终输出仍需独立检查，不从测试源码存在推断通过。
- [矢量验收记录](../../../../docs/verification/inline-vectors.md)记录已完成的 1 页、3 资源、8 次呈现样例：PDF／SVG 实际路径和基线、PDFium 原 TeX 搜索／选区、四种渲染输出及 5 项负控制均符合协议，整页已复查。它复用示例内既有 TeX 转换器，不增加生产解析依赖，也不证明真实文献或任意公式兼容。
- 官方回退的两篇 17 页输出已独立结构核查及双引擎逐页比较，68 次同引擎基线像素比较全等、联系表逐页复查未见新增截断或错位；本地证据在 `build/verification/fontbox-rollback-official-20261112/literature-formal/verification.json`。该证据在新增原生混排／矢量接入之前，不能替代新路径的最终验收。
- 新隔离调用方的 17 页[真实文献验收](../../../../docs/literature-pdf-integration.md#本次真实文献)另行通过：全文内容流顺序不变，27,077 个稳定字符框精确相同，3,416 处源空白分隔保留；9 个转原生字符取得真实框。34 次双引擎同引擎比较仅 32 次全等，中文第 2 页的原生字形、精确表头提取置换及旧退化空格单像素差异单列约束，全部页面和差异图已经复查。文献 29 处公式仍为 PNG，不能从独立矢量样例推断已批量转换；本次没有重新测量性能。

## 适用范围

适用于明确资源的高层矢量合作入口与默认文字／图片混排的有限原生输出。Heading／列表、XML v1、任意公式语言及未建模的跨格式语义不自动获得矢量支持。调用方仍需限制解析前输入、明确字体和质量，并检查实际导出损失与真实输出。
