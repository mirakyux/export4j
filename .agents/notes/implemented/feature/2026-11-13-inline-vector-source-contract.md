# 工程笔记：矢量的原子来源与逻辑阅读文字分离

状态：已实现

## 先说结论

调用方已生成的公式轮廓通过不可变 `VectorResource`／`InlineVector` 接入语义段落及单元格。几何与逻辑阅读文字构成同一个原子值，原始来源只占一个 UTF-16 单元；不把多字符 TeX 的长度当作来源跨度，也不让模板仅改文字却复用旧轮廓。

## 问题

文献中的公式图片可以保留视觉，却无法仅靠图片替代文字获得 PDF 中的公式阅读原文。直接借用低层轮廓又容易漏掉模板、编辑、重放、表格预算和跨格式保存。尤其当一枚 U+FFFC 的轮廓包含多字符逻辑文字时，按阅读文字长度推进来源会使后续文字外链或来源范围错位。

图片混排也有独立边界：整行轮廓保留视觉及 ActualText，但忽略 ActualText 的普通提取器无法还原原生文字。修复来源不等于可以把复杂塑形结果直接按单字重新输出。

## 决策

- [模型 API](../../../../docs/inline-vectors-api.md) 使用自有有界段类型，无第三方或 AWT 句柄；快照、有限数值、子路径顺序、尺寸、段数和阅读文字在模型边界验证。资源 ID 包含尺寸与规范化坐标，规范字节预算不冒称实际堆大小。
- `Paragraph`／`TableCell` 保留所有旧构造器，新增矢量来源视图；`mixed` 统一生成原子标记、默认样式及外链。复制、模型压缩、模板和整体编辑保留同一资源；块单元格不通过旧视图隐藏后代。
- [TextOutline](../../../../export4j-text-core/src/main/java/com/mirakyux/export4j/text/TextOutline.java) 明确区分 `sourceLength` 与 `logicalText.length()`；旧文字构造器保持原长度，矢量原子消费 1。外链和后续来源使用前者，PDF ActualText 使用后者。
- 普通输入按唯一几何计源预算，重复绘制计呈现工作；流式输入按出现次数保守计几何，避免全流资源 ID 无界驻留。模板、编辑和页区另有各自工作预算。
- 变宽候选准备及重试也累计逻辑阅读文字和几何工作，不能只按一枚 marker 收费；在转换路径前按出现次数预检段数，避免先复制大轮廓再发现预算超限。单次转换可局部共享不可变路径，但不引入跨会话缓存。
- 普通 HTML／Markdown 矢量资源只接受明确登记的键，不隐式解析 TeX／SVG或取网络资源。无对应语义的 Web／DOCX 出口默认失败，仅明确 DEGRADE 才保留逻辑文字并报告损失；XML 静态路径扩展见 [ADR-0116](../../../../docs/adr/0116-mixed-semantic-blocks-and-static-vectors.md)。
- 仅图片混排的安全 LTR、静态 TTF、一字一 GID、无装饰／字段／矢量行可复用既有塑形坐标发出原生字形。任一条件不满足则整行保留原轮廓；不改测量、不猜 Unicode、不抹去复杂塑形。底层编码继续遵循[原文／字形分离](../bug-fix/2026-11-12-pdf-unicode-glyph-aliases.md)。

## 考虑过的备选方案

- 一律将 TeX 光栅化：能保留视觉，但图片 alt 不等于 PDF 中保留原 TeX，不作为唯一合作入口。
- 把公式解析器和第三方公式类型放入核心 API：扩大依赖及执行预算边界；由调用方生成有界轮廓即可满足当前接入。
- 模板只插值 `logicalText`：会产生文字与图形不一致；动态公式须整体重建。
- 将全部图文混排改为逐字原生字体：会破坏连字、组合簇、双向及复杂脚本。采用可证明的一一映射子集，不能证明时保留原路径。
- Web／DOCX 静默转文字或 XML 静默丢资源：生成成功却损坏后续保存／恢复，改为明确策略或拒绝。

## 后果

高层接入不再依赖自定义组件，轮廓与原 TeX 可以一同保留；代价是额外原子来源及工作账本。底层矢量仍是绘制资源，不自行成为可编辑公式树；可选数学模块可另外生成受限原生 Word 目标，但不提供通用 TeX↔OMML、完整 LaTeX、通用 SVG 或跨格式无损恢复。ActualText、普通提取、搜索和选区仍需按独立工具分别验证。

FontBox 继续使用官方依赖，补丁构建选项已经完整移除，决定与生命周期理由见[有界文字与 PDF 复用](../simplification/2026-11-12-bounded-text-pdf-reuse.md)。新的文字表示不能据此宣称字体解析内存下降，也不以低质量图片或公式换取指标。

## 验证

- [InlineVectorTest](../../../../export4j-model/src/test/java/com/mirakyux/export4j/model/InlineVectorTest.java)覆盖防御快照、规范化身份、非法几何与原文、marker 冲突、模型复制、模板／编辑原子性及预算。
- 模型、布局、文字、流式重放、Web／DOCX／XML 的相关回归与本地构建通过；变宽长逻辑文字回归证明每次候选准备都计费，跨组流式回归证明全流预算不被分组重置。最终输出仍需独立检查，不从测试源码存在推断通过。
- [矢量验收记录](../../../../docs/verification/inline-vectors.md)记录已完成的 1 页、3 资源、8 次呈现样例：PDF／SVG 实际路径和基线、PDFium 原 TeX 搜索／选区、四种渲染输出及 5 项负控制均符合协议，整页已复查。它复用示例内既有 TeX 转换器，不增加生产解析依赖，也不证明真实文献或任意公式兼容。
- 官方回退的两篇 17 页输出已独立结构核查及双引擎逐页比较，68 次同引擎基线像素比较全等、联系表逐页复查未见新增截断或错位；本地证据在 `build/verification/fontbox-rollback-official-20261112/literature-formal/verification.json`。该证据在新增原生混排／矢量接入之前，不能替代新路径的最终验收。
- 新隔离调用方的 17 页[真实文献验收](../../../../docs/literature-pdf-integration.md#本次真实文献)另行通过：全文内容流顺序不变，27,077 个稳定字符框精确相同，3,416 处源空白分隔保留；9 个转原生字符取得真实框。34 次双引擎同引擎比较仅 32 次全等，中文第 2 页的原生字形、精确表头提取置换及旧退化空格单像素差异单列约束，全部页面和差异图已经复查。文献 29 处公式仍为 PNG，不能从独立矢量样例推断已批量转换；本次没有重新测量性能。

## 适用范围

适用于明确资源的高层矢量合作入口与默认文字／图片混排的有限原生输出。标题／列表混合对象和 XML v1 静态路径已由 ADR-0116 扩展；原有 17 页证据不证明该新增路径。任意公式语言及未建模的跨格式语义仍不自动获得支持。调用方需限制解析前输入、明确字体和质量，并检查实际导出损失与真实输出。

## 可选公式封装

上述来源契约继续适用于底层矢量。可选 `export4j-math` 在其上封装受限 TeX 和 Markdown 识别，并分别绑定原生 Word 数学树；核心仍不解析公式。模块边界与未采用方案统一见 [ADR-0113](../../../../docs/adr/0113-optional-bounded-math.md)，API 与实际验收见[公式指南](../../../../docs/math-api.md)。不把该扩展改写为旧示例已提供公共解析能力。

## 源内容编译与继承的延伸

[ADR-0115](../../../../docs/adr/0115-source-content-options.md)把逐块解析与继承放在编写／绑定阶段：`ContentOptions` 逐属性解析，`SourceContentParser.Session` 按解析器身份在整次绑定中累计预算，最终模型仍只保存已完成的语义块。静态源与整字段源只绑定一次，解析产物的 `${...}`、链接和逻辑阅读文字不再插值。

- 解析前预算必须约束即将执行的工作，而不只是检查最终树。公式轮廓生成前预留阅读文字、对象位置、模型节点和线段额度；回调不可在额度已知不足时仍执行。第三方语法树的保守复杂度预留是输入策略，不是 JVM 堆沙箱。
- 临时占位符的避碰须覆盖语法解码后的值和显式资源键。只扫描原始源串会漏掉 HTML 实体解码后的正文／图片目标，可能把用户文字误替换成内部公式资源。关闭解析时仍须保留原始表格和 TeX，不能交给另一轮语法处理改写。
- 按对象身份登记的动态格内容要求相同的缓存键语义；存在这类声明时，页区不能仅按 `equals` 合并，否则会跳过另一份格内容及其错误。相等页区的独立执行和失败传播由 `DocumentTemplateSourceTest` 回归保护。
- 字体角色和资源键属于不同契约；空角色合法选择调用方显式默认字体。HTML 字体族映射复用 `TextAppearance` 验证角色，不能套用非空资源键校验。

行为回归、模型等价、完整 PDF 双引擎输出和明确 DOCX 损失统一见[源内容块验收](../../../../docs/verification/content-blocks.md)。这里记录跨层根因，不把源矢量导出为逻辑文字称作原生 Word 数学。

## 混合语义块与双目标编译的后续决定

[ADR-0116](../../../../docs/adr/0116-mixed-semantic-blocks-and-static-vectors.md)将同一原子契约扩展到标题／列表与 XML v1 静态路径，避免普通段落支持对象而语义包装层、保存或编辑重新丢失对象。旧文字便利签名保留，混合内容使用独立新增入口；不通过放宽兼容性基线掩盖公共泛型签名变动。

[ADR-0117](../../../../docs/adr/0117-single-source-math-representations.md)在可选模块内一次生成视觉与原生 Word 两个表示。公式按本次出现身份绑定，不能按相同 TeX 或值相等轮廓认领；表示回退逐目标显式记录。容器宽度、缩进及跨度属于源编写阶段拟合，后端仍只消费最终绘制或语义目标。

显式文字字体通过局部 Atom／Box 提供实际轮廓，避免修改全局上游字体映射或隐式查找系统字体。配置只保留有界私有编码字节；字体权限在配置边界用无保留加载器验证，字形轮廓逐字形计入预算。配置生命周期与正文缓存过期分开，不能把“局部解析字体已不再引用”写成“编码字节或进程 RSS 已释放”。API 子集及验收结果分别见[富内容指南](../../../../docs/rich-content-api.md)和[富内容验收](../../../../docs/verification/rich-content.md)，旧 17 页结果不自动证明这些新增路径。

原生数学运行应在模型归一时解析继承后的字号，显式数学字号优先；即使公式占位符与宿主段落字号相同，也不能省略标准运行字号并依赖段落标记继承。独立阅读器自身的字号缺陷须与生成器问题分别定位，不能为了适配错误渲染而改写标准几何。回归覆盖正文、标题、列表、物理单元格、局部覆盖及严格回读。

[ADR-0118](../../../../docs/adr/0118-configured-export-entry.md)将重复装配收拢到外围 starter，核心不反向依赖后端。便捷入口必须按实际目标选择投影：PDF 不应因为 OMML 尚未支持同一公式而失败。声明级覆盖与完整解析值也不能混用，后者会把正文默认值错误地变成标题和单元格的显式覆盖。正文、数学文字及 Word 槽位来自同次显式字体配置，但公式文字快照只在本次操作实际需要时准备；不能为减少参数而永久保留解析对象、猜测脚本字体或接受后忽略 CSS 字体族。

公式数量、全篇文字提取和对象最小行距不足以证明格内布局正确。真实验收将源物理格、阅读器标准表格／公式 MCID、实际字形与格线分别绑定，检查公式越格及字框边缘相交；图片则按实际绘制出现核对内容、透明度及完整可见区域，不能只清点资源字典。最终结果和指定阅读器边界归入上述富内容验收，不把开发版阅读器通过扩展为通用 Word 兼容。
