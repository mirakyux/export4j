# 工程笔记：静态文档站的模板试验台边界

状态：已实现

## 先说结论

文档站使用独立的浏览器预览器演示 XML 模板与 JSON 数据绑定，不搬入依赖 Java 服务的完整设计器。浏览器只提供明确语法子集的近似排版；正式文档仍由 Java 引擎生成和验收。

## 问题

静态站需要让读者直接修改模板并看到数据绑定结果，但不能依赖后端。浏览器文字测量、系统字体和表格布局与 Java 引擎不同，将浏览器结果包装成正式输出会误导调用方。直接处理用户源码还会引入脚本执行、数字精度丢失、循环展开过量和草稿丢失等问题。

## 决策

- [模板预览器](../../../../site/.vitepress/theme/playground-engine.mjs)单独实现受控子集，不调用 Java 设计器接口。先验证完整静态结构，包括未选中的条件分支；不支持的节点、属性和数据显式报错，不以静默忽略换取表面可用。
- 通过 DOM 节点和文本绑定构造输出，不执行模板表达式或把输入直接作为 HTML。点路径仅访问自有属性并拒绝原型相关名称；[编辑界面](../../../../site/.vitepress/theme/Playground.vue)将输出放入空 `sandbox` 的 iframe，输出自身再通过 CSP 禁止脚本、网络资源、表单和基址修改。
- JSON 数字保留原始字面量并仅用于文字显示，不先转换为 JavaScript 浮点数。文件下载直接使用编辑原文，避免重新序列化改写大整数、小数或指数形式。
- 源码、解析深度、节点、循环和展开内容分别设限。插值须在每段文字拼接前扣减全局展开预算，标题、作者和 literal-text 同样计费；先拼出字符串再检查长度无法限制中间分配。
- 草稿仅保存在当前浏览器。输入时防抖保存，并在 `pagehide`、页面隐藏及组件卸载时同步保存，补足防抖窗口内立即刷新造成的最后一次输入丢失。默认示例不自动变成用户草稿；真实编辑后的草稿跨语言页面保留原文。
- [节点树操作](../../../../site/.vitepress/theme/playground-tree.mjs)按 XML 源范围插入和移动，避免序列化整棵 DOM 改写属性、注释、CDATA、数字和绑定原文。修改前核对树对应的源码版本，修改后重新解析；偏移量节点标识不跨源码版本保存折叠状态。
- 插入和移动共用结构约束，保护页面配置、表格跨度、条件分支和循环变量作用域。预览与节点树独立解析，JSON 错误不阻止继续修 XML；XML 错误时禁止按旧树修改源码。
- 源码输入和结构编辑共用撤销历史，最多保留 50 个状态、合计 2 Mi UTF-16 单元；历史只在当前会话内保留。拖放之外保留点击插入、上下移动及键盘操作，手机树区域单独滚动，插入与移动按钮保持可见。
- 示例和缩放使用[自定义下拉](../../../../site/.vitepress/theme/PlaygroundSelect.vue)，菜单跟随站点浅深色变量，避免原生弹出菜单的系统配色与页面文字颜色叠加。全站表面和预览画布采用中性灰，交互用蓝色强调。

支持语法、使用方式和正式输出边界以[公开文档站说明](../../../../docs/documentation-site.md)为准。

## 考虑过的备选方案

- 将完整设计器直接放到静态站：现有设计器需要 Java API 和真实布局快照，无法满足无后端入口。
- 以浏览器打印提供“正式 PDF 导出”：无法保证 Java 字体、换行和分页契约，未采用。
- 静默跳过不支持的 XML：会让预览遗漏内容而无法发现，不适合帮助读者编写可交给 Java 使用的模板。
- 用 DOM 序列化实现节点树编辑：会重写未编辑的源码，也难以保留用户格式和注释，未采用。

## 后果

读者可以离线编辑、导入和下载源码，无须上传数据；站点也不增加服务端运行依赖。代价是维护一个有限预览子集，且浏览器结果不能证明 Java 自动分页、资源包或复杂排版可用。浏览器存储不可用时仍保留编辑和预览，需下载源码保存内容。

## 验证

- [中英文示例](../../../../site/.vitepress/theme/playground-samples.mjs)共六份，经 Java `XmlTemplate.compile` 与 `DocumentTemplate.render` 检查通过；这只证明源码语法和语义绑定，不证明两种布局等价。
- 浏览器独立探测通过 33 项检查，覆盖原型路径、文字注入、数值原文、未选中分支验证，以及单段插值、元数据和 literal-text 的展开预算。对应边界可在[预览器](../../../../site/.vitepress/theme/playground-engine.mjs)核对。
- 生产静态构建与 36 项浏览器交互检查通过，包括双语示例、原文导入下载、输入后立即刷新、草稿恢复、语言往返、存储失败、四种视口和深色模式。手机及横屏预览滚入屏内后实际查看；离屏 iframe 的整页截图不能证明内容已绘制。
- canonical、语言互链、站点地图、真实 404、许可文件、按需加载与 iframe 隔离分别检查通过；正式域名已复验工具交互，工具页及样张 PDF 与发布源摘要一致。
- 网络检查分别观察 iframe 与主页面。正式域名的 Cloudflare 托管层会注入性能统计脚本，应单独记录；带标记的编辑输入未出现在请求 URL 或请求体中，预览 iframe 未发起 HTTP 请求，不能将托管脚本请求误当作模板上传，也不能把这一组探测扩大为任意脚本的隐私保证。
- 节点解析和源范围操作通过 66 项独立浏览器检查；六份双语示例插入全部五类节点并移动后，经真实 Java 编译与数据绑定通过。结构组件通过真实鼠标拖放、触屏替代操作及非法落点检查；父界面验证了拖放后 XML、撤销／重做精确恢复、预览顺序和 JSON 错误时继续编辑结构。
- 2026-11-14 提交前修正节点树误拒多行表头：表头允许连续多行，仍须全部位于正文行之前。结构检查扩为 72 项，恢复旧逻辑的负控制可识别三个合法编辑被拒的场景；生产构建后的 36 项工具交互和 5 项父界面集成重新通过。此处为本地提交验收，线上字节须在后续部署时另行核对。

## 适用范围

适用于文档站的 XML＋JSON 模板试验台，不改变 Java XML 适配器、Java 布局预算或完整设计器契约，也不把有限浏览器输入检查解释为通用恶意文档处理能力。
