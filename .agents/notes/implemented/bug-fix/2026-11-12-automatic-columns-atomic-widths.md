# 工程笔记：自动列宽保留行内对象的原子下限

状态：已实现

## 先说结论

只含 Fixed／Auto 的语义表格在分配列宽前，先满足行内图片与字段的不可拆分宽度。首选宽度可以压缩，这个内容下限不能压缩；显式最大列宽和页面宽度仍须满足。

## 问题

旧分配器在页面不足时，将各 Auto 列按首选宽度比例压向调用方配置的最小值。长文字提高了相邻列的首选宽度，可能把另一列压到小于图片／字段宽度，随后报 `GLYPH_TOO_WIDE`，即使页面存在可行分配。真实文献接入不得不在桥接中另行扫描图片并抬高列下限。

## 决策

- [列宽分配器](../../../../export4j-layout-core/src/main/java/com/mirakyux/export4j/layout/core/DocumentLayouter.java)计算每个真实锚点的最宽图片／字段，加上一次左右内边距，作为覆盖列区间的约束。多个可以独立换行的对象取最大宽度，不相加。
- 区间按右边界排序，从右侧 Auto 的剩余最大容量补足，使重叠跨度能够共享已满足的列宽。后续首选宽度增长及压缩都以该有效下限为基准，保留原行列、UTF-16 来源与预算计费。
- 只有含 Auto 且无 Fraction 时启用。比例列依赖最终剩余空间，不能把混合跨度的需求直接灌给 Auto 列，造成新的可行表误拒绝。

## 考虑过的备选方案

- 继续要求调用方扫描图片：业务桥接重复实现布局责任，字段与合并格也容易遗漏，未采用。
- 对合并区均分下限：重叠合并区可能各自向两侧索取宽度，拒绝本可共享中列的布局，未采用。
- 缩小图片或突破 Auto.max：改变显式内容几何，未采用。

## 后果

普通文字仍按既有首选规则换行；图片与字段不会因相邻长文字而被压到不可绘制。代价是增加有界区间约束计算；含 Fraction、块格和单向表的既有范围保持，不能据此宣称通用表格约束求解。

## 验证

[既有列合并测试](../../../../export4j-layout-core/src/test/java/com/mirakyux/export4j/layout/core/ColumnSpanLayouterTest.java)先复现单格和合并格失败，再覆盖图片、字段、多原子对象、Fixed／Auto、重叠跨度、最大列宽／页面不足及小数上界舍入。布局模块 278 项测试通过；独立四页输出保留 60 pt 图片、80 字符正文及最终页字段。两篇真实文献移除桥接手工下限后仍成功，复验范围与提取限制见[接入指南](../../../../docs/literature-pdf-integration.md)。

## 适用范围

适用于普通语义 Table 的 Fixed／Auto 列分配。它不引入公式模型或矢量公式资源入口，也不修订 PDF 轮廓混排的 ActualText 提取兼容契约。
