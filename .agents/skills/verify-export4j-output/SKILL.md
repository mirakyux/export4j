# 验证文档输出

## 准备样例

1. 从[验证矩阵](../develop-export4j/references/verification.md)选择受影响契约的实际 Gradle 任务、`scripts/verify_*.py` 和既有阶段记录，先确认入口及参数存在。
2. 使用项目隔离 Python 环境安装 `scripts/requirements-verification.txt`，核对实际版本；需要时准备 Poppler、veraPDF、OpenSSL 或 Word。不得借工具版本变化放宽内容断言。
3. 先运行对应构建和样例。公共契约变化运行 `build sbom publishLocalBundle` 及 `scripts/verify_local_consumer.ps1`，使用本次成功输出。
4. 生成物、截图、原始日志及报告写入被忽略的 `build/`；共享文档只记录脱敏结论、相对样例位置及可复现命令。

## 按证据层次验证

| 层次 | 需要证明的行为 |
| --- | --- |
| 模型／IR／几何 | 来源、尺寸、分页、边界、预算与错误契约 |
| 文件结构 | PDF 对象／字段／链接，OOXML 包／关系／标准元素，SVG／PNG 的实际内容 |
| 独立工具 | 选择对应 Python 验证器，核对文字、坐标、字体、图片及资源 |
| 独立渲染 | 检查全部新增或变化页面；相关条目要求双渲染时使用不同引擎 |
| 阅读器操作 | 仅在实际要求时验证打开、字段更新、编辑、保存及回读，各自登记结果 |

- 不以生成成功、HTTP 状态、文件大小或同一库读回替代最终内容检查。
- 检查来源顺序、正文唯一性、重复表头、最终页码／目标和链接矩形。提取文字、ActualText、查询、选区和视觉显示是不同证据。
- PDF 表单检查字段树、widget、值及外观流；自动填写保存不能冒充人工阅读器验证。PDF/A 需要独立合规验证，签名需要独立验签及篡改拒绝。
- DOCX 的标准 OOXML、严格损失诊断和指定语义子集分别检查；不承诺一般 Word 无损往返或与 PDF 分页一致。
- 视觉基线差异先定位原因。只有明确的预期变化并检查全部相关页后才能更新；不得为获得通过结果自动使用 `--update-baseline`。

## 调用方与容量

隔离调用方使用 `build/verification/consumer-build-directory.txt` 指向的本次成功目录，或验证器支持的显式 `--consumer-build-directory`。核对目录确实来自本次命令；不拿旧文件冒充新验证。

容量验证使用已有压力脚本与受控参数，分别报告堆、进程工作集／私有字节、句柄、吞吐和临时磁盘。堆峰值不等于 RSS；只证明采样场景。单向布局的有界内存不代表 PDFBox 页树恒内存或长期无泄漏。

## 交付证据

说明样例与工具版本、实际命令、观察结果、未覆盖边界。共享验收文档保留必要可复现条件，不包含机器路径、私有文件或原始日志。未安装工具、阻塞的阅读器步骤和未完成检查必须如实注明。
