# 编写稳定测试

## 选择验证

1. 先说明可观察行为与失败触发条件，找到已有测试及[验证矩阵](../develop-export4j/references/verification.md)。
2. 优先扩展既有测试；低影响文档修改验证链接与事实，不为访问器、命名同步或实现细节堆测试。
3. 选择能识别回归的断言，涵盖正常、边界和失败路径。不要用同一段算法同时生成期望值和实际值。

## 确定性与隔离

- 固定显式字体、资源、区域、排序与配置；不依赖系统字体、真实网络、个人目录、默认时区、当前时间或机器速度。
- 文件测试使用临时目录；并行案例不共享输出名、文档级可变状态或缓存。只有需要验证原子覆盖时才显式创建旧目标。
- 需要线程或子进程的测试使用可观察事件／同步原语。每个等待和子进程都设有界超时，并保证失败后清理；不用固定 sleep 代表完成，不以整个构建的超时替代局部上限。
- 使用 try-with-resources／finally；断言失败、取消、异常时也必须关闭源、文档、流、进程和临时资源。验证借用流与拥有流的契约差异。
- 几何断言说明单位和误差来源；不要通过扩大容差、删断言、自动更新视觉基线或关闭校验掩盖失败。

## 引擎回归重点

| 变更 | 有意义的断言 |
| --- | --- |
| 布局／分页 | 来源顺序、内容唯一性、页区边界、推进与过高内容失败 |
| 文字／字体 | 实际字体角色、UTF-16 范围、簇边界、测量与绘制一致 |
| 表格／组件 | 锚点与物理列、重复表头、片段顺序、短区不消费、来源预算 |
| 配置／Builder | 加入时快照、显式属性意图、恢复单项、回调不泄漏可变对象 |
| I/O／流式输出 | 单次源、有限预读、关闭先后、主／suppressed 异常、旧目标保持 |
| 安全解析 | 零外联、非法输入拒绝、预算／取消、脱敏诊断 |

输出文件验收继续使用[独立验证技能](../verify-export4j-output/SKILL.md)，不要仅以写出文件或相同后端读回为成功。

## 运行与判断

Windows 可运行 `.\gradlew.bat :export4j-layout-core:test`，需要定位案例时加 `--tests` 指定实际类名；其他模块按真实归属替换。Linux/macOS 使用 `./gradlew`。跨模块契约扩大到 `build` 及对应示例。

使用 Gradle 生成的 `build/test-results/test/` 与 `build/reports/tests/test/` 定位失败及耗时。重跑用于验证具体假设，不反复运行直到偶然通过。明确区分失败、未执行和环境前置条件缺失，不将跳过算作通过。
