# 架构约束

- 保持 `Document Model → Layout Engine → Layout IR → Display List → Backend` 的职责分离。
- 生成、导入、编辑及转换不得依赖打印机驱动、打印服务或 Office／浏览器进程；普通路径支持无桌面 JVM。外部应用只用于独立兼容性验收，不进入生产调用链。
- 文档模型只表达语义和项目自有值类型，不包含 PDF 对象编号、PDFBox 类型或后端句柄。
- 测量与布局阶段不写入目标文件；后端不得再次决定换行和分页。
- DOCX 与 HTML／Markdown 导入、导出直接映射文档模型。PDF 原对象处理独立，语义恢复通过显式损失通道生成模型；不强制经过 Display List，也不把第三方对象交给布局核心。
- DOCX 专有语义保留在适配器自有、不可变的类型化模型中，使用块 ID／UTF-16 锚点连接通用正文；不把原包或 XML 片段冒充模型。投影到通用文档时逐项报损。HTML 显式 CSS 布局模式可以编译为组件树，仍由共享布局及最终语义解析决定位置，后端不处理 CSS 或重新排版。
- PDFBox 文档与绘制库只进入 PDF 后端与 PDF 适配器；FontBox 及其 I/O 基础库可封装在字体模块内部，公共签名不得暴露它们的类型。DOCX 专用实现依赖只进入 DOCX 适配器。专用测试可依赖它们验证结果。
- 公共 API、公共异常、SPI 和传递暴露的返回类型不得泄漏第三方实现类型。
- 模块依赖保持单向、无环。核心模块不反向依赖后端、适配器、示例或测试工具。
- 组件扩展通过核心定义的接口接入，布局核心不得反向导入组件实现。
- 普通 `ComponentBlock` 整块移动；实现核心 `PageableComponent` 的组件返回有序非空片段，可适应首片段剩余高度。每片段须放得进新页，固定区域调用要求单片段。平衡多栏会有界重复测量，自定义子组件必须确定、可重复调用。自定义组件是可信代码，须返回平衡且有界的本地绘制，并自行声明线程安全。
- `PageTemplate` 必须先预留页眉页脚，再分页正文。目录使用独立前置页和固定页码列；书签、链接、评论和表单在目录页偏移确定后解析，最终页字段统一合成。
- 交互数据使用后端中立的 `DocumentExtras`。PDF 表单同时验证字段树、页面 widget、当前值和外观流，默认保持可编辑。空字体列表保持 ASCII Helvetica；Unicode 字段完整嵌入一个显式字体，下拉框与单选组也保留默认值和外观。表单初始值缺字须失败，不套用正文占位符策略。
- 分节的物理页索引与显示页码分离；首页／奇偶模板先预留最大页区。目录、书签、引用和字段只在最终页偏移确定后解析。脚注每节单调预留，带高最多为原正文 40%，按完整行续页，当页新脚注至少显示首行，容量不足明确失败。引用使用有界多行预留，禁止无上限重排。
- 行内字段占一个 U+FFFC 原文位置，按固定宽度整块换行；最终值只替换行内轮廓，不改行宽、来源范围或分页。值不能完整放进预留框就失败。显式注释标记须唯一绑定同段落 `Note`；旧段末标记保持兼容。正文警告使用原文 UTF-16；生成值警告使用局部 UTF-16，region `INLINE_FIELD:<原始位置>` 区分来源。未解析字段不得绘制；语义表格单元格支持页码／总页数／页码引用／编号引用，按每次实际呈现解析重复表头，保留拆行来源及行列诊断；单元格注释标记仍拒绝。DOCX 原生字段、显式宽度与严格损失边界见[字段指南](../../../../docs/docx-fields-api.md)和 [ADR-0016](../../../../docs/adr/0016-native-docx-fields.md)。
- `DocumentEngine` 位于组件模块，通过 `DocumentBackend` 接受输出后端；不为统一入口反向引入具体后端。SVG／Raster 拒绝非空交互数据；不得无提示丢弃评论、字段、链接或书签。DOCX 映射语义模型，严格模式拒绝不支持的格式／继承／编号，允许损失模式必须返回诊断；宏无条件拒绝。
- 模型 `processing` 统一导入／编辑／导出的动作与损失：操作、功能、格式、默认值依次覆盖；ERROR 默认，WARN／IGNORE 使用同一明确处理，IGNORE 仍返回实际损失。跳过、降级、丢弃和保留不能互换；没有真实保留通道就失败。预检绑定不可变候选及确切编码，I/O 成功才返回 ACTUAL；未编辑内容也检查损失。
- PDF 读取／静态复制、页级编辑、被动对象、渲染、优化和语义恢复各有独立子集，不互相放宽预检。普通裁剪／覆盖不是删除；光栅脱敏清除像素并新建图片 PDF，选择性脱敏在明确静态子集中重新构建保留字形／像素／剩余路径，两者均不得复制被删源流、隐藏文本、附件和历史。恢复来源框不是精确脱敏框。权限、签名、非法输入、预算和取消不能由损失策略绕过。
- 无障碍逻辑顺序和命令绑定由后端中立 `AccessibilityTree` 持有；显式模型桥不重测或分页。绘制命令索引变化必须重建绑定，不能静默丢树；PDF 后端显式选择 PDF/UA-1，普通输出不自动合规。信任／PAdES／归档标准使用独立入口和最终文件验收，不把完整性验签视为信任判断，见[ADR-0097](../../../../docs/adr/0097-explicit-pdf-editing-recovery-and-standards.md)。
- 自主设计核心模型与布局算法。通过依赖复用成熟基础设施，不复制其他项目的实现、注释或测试代码。
- 静态矢量标记通过 `InlineGraphic` 显式 U+FFFC 位置参与共享测量，轮廓须位于预留框且有界，不请求标记字体字形。`FormText` 保留原 UTF-16 位置及选择状态；普通标签继续执行字体策略。静态控件不等于可编辑表单、DOCX 语义或 PDF/UA。组件语义贯通须保留来源、变换、待解析字段、外链及全局预算，不能以提前绘制或转成网格静默丢失语义。
- 语义表格续排的 `fragmentIndex/fragmentCount` 与页码、栏号分离；同宿主、同 Table 实例及字体策略的完整连续序列才属于同源。组合和字段解析原样传播序号，全文档再次校验。源预算按唯一源计数，片段／表头行／字段／链接按实际呈现计数；完整源重复不可通过去重放行。FontScope 必须保留全部短初始区域。
- 格内 SemanticTable 使用核心 TableCursor 一次测量后按实际可用高度取片段，空取片不消费来源／输出预算。GridSemanticStreams 只终结当前网格登记并验证的连续流和缓存表头，临时序号不得逃逸；全局 Registry 不放宽独立重复源。行列及 UTF-16 属于内 Table，不能冒充外网格格坐标。内／外拆行开关独立，自定义组件和嵌套网格仍原子。
