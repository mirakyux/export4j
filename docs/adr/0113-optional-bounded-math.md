# ADR-0113：可选的有界公式转换与 Markdown 识别

- 状态：已采纳
- 日期：2026-11-13

## 背景

[ADR-0108](0108-native-docx-math-and-example-typesetting.md)建立了适配器自有的 Word 数学树和示例内 TeX 矢量排版。公共库已有 `InlineVector` 和 `DocxMath`，但使用端仍需重复实现分隔符识别、字体轮廓捕获及有限 TeX→OMML。只暴露低层底座使错误分类、上下文保护和预算难以保持一致。

## 决定

新增可选 `export4j-math`，仅向既有模型和 Web／DOCX 适配器依赖。`TexMath` 提供矢量与受限原生树转换，`MarkdownMath` 使用真实 Markdown 源码上下文识别，再接入现有导入器；核心、布局与后端不反向依赖。

矢量入口先做完整源码预算及受限语法检查，再调用封装的 JLaTeXMath。字体来自固定的五款 Computer Modern 资源，轮廓以并集保留重叠墨迹，捕获与最终曲线都计入预算。原生入口独立解析明确子集，不能推断的运算对象范围和结构直接拒绝；不将未知语法伪装成普通数学运行。

Markdown 保留原 UTF-16 范围并跳过代码／链接／资源／原始 HTML 上下文。公式每次出现独立绑定；可编辑 Word 使用实际段落和单个对象槽，表格正文按需提升为有身份的格内段落。读取器生成的临时身份不得把无锚点普通表头误判为块内容；真正被原生语义引用的身份继续保留。

默认严格错误。显式保留源码的降级逐式报告，不放宽普通 Markdown 损失策略，预算和取消不降级。没有图片失败后无上限重试，也没有文档或公式的全局缓存。

## 备选与代价

- 继续让使用端各写一套：依赖少，但分隔符、预算和原生锚点会重复出错，不能满足公共库接入需求。
- 将解析器放入核心：增加所有调用方的 Java2D 和第三方依赖，违反按需依赖边界，未采用。
- 把任意 TeX 直接交给上游：无法控制宏扩展、字体及工作量，未采用。
- 把所有公式转图片／源码：丢失曲线或可编辑结构，不能作为默认成功路径。

可选模块引入 GPL-2.0-or-later 加原始 linking exception 的私有运行依赖；制品携带许可、未修改上游源码及构建材料，BOM／SBOM 和隔离消费必须覆盖它。库内锁不能隔离同 JVM 外部直接修改 JLaTeXMath 全局状态的代码，该用法不支持。

## 验收及边界

见[公式 API](../math-api.md)与[验收](../verification/math.md)。检查源码范围、重复公式、表格及样式、严格 OMML 往返、预算／取消／降级、并发和显式字体；真实制品消费及 PDF 双引擎、SVG／PNG 独立渲染分别登记。该决定扩展 ADR-0108 的示例封装边界，不引入跨格式通用数学节点、完整 LaTeX、MathML 或 OCR。
