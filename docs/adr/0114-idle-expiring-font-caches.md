# ADR-0114：字体缓存按内容寻址并在空闲后释放

- 状态：已采纳
- 日期：2026-11-13

## 背景

相同字体反复加载会重复建立不可变字形映射；独立 PDF 导出还会重复解析水平 TrueType 程序。会话内缓存无法复用已经完成的导出，而长期全局持有所有字体会延长较大源快照及惰性表的存活。

## 决定

字体加载入口默认使用有条目、编码源字节及空闲时间上限的 `FontFaceCache`。键为输入快照内容 SHA-256，每次仍执行调用方输入预算；不按路径或字体名复用可能已变化的程序。外部数组、借用流、嵌入许可及错误语义不变。

PDF 后端默认使用独立的 `PdfFontCache`。仅解析后的水平 TrueType 程序跨导出独占借用；不共享文档、PDFont、COS、子集或页级 pin。租约归还后开始计空闲时间，活跃租约不会因过期、clear 或 close 被提前关闭。会话内 LRU 与子集快照保持原有边界，普通一次性导出不顺带启用流式子集快照。

到期释放无需新的导出触发。维护使用惰性守护任务，不继承请求线程本地状态或上下文类加载器，不执行解析／布局／输出；空缓存及关闭时终止维护线程与排队任务。清理异常显式可观察，不吞掉资源释放失败。测试注入单调时钟／受控调度，另以事件和有界等待核对真实自动释放。

默认加载缓存为 16 项／64 MiB，PDF 池为 8 项／32 MiB，文字路径基础物理字体为 32 项／64 MiB；默认空闲时间均为 5 分钟。上限是源权重，不代表真实堆或进程内存。超过容量时走本次独立加载／解析，不放宽原有输入或导出预算。

## 备选与代价

- 仅要求应用复用 `FontFace`：可以继续使用，但不足以减少未改造调用方和 PDF 后端的重复解析。
- 全局无限保存或只依赖软引用：无法表达容量及空闲释放契约，未采用。
- 仅在下次请求时清理：空闲服务可能一直保存最后一批字体，未采用。
- 将整个现有 PDF 会话缓存设为静态：会混合借用标记、子集和关闭所有权，未采用。
- 系统字体磁盘索引：不替代解析对象复用，且不符合当前显式字体来源边界，未引入。
- 持久化或修改第三方解析对象：增加格式、版本及维护责任，未采用；继续使用官方固定 FontBox 制品。

维护线程是同步文档执行规则的限定资源清理例外。缓存延长部分字体的存活以换取重复工作减少；实际收益须用相同输入、算法和 JVM 条件验证。释放缓存引用不使应用仍持有的字体失效，也不保证垃圾回收或 RSS 立即变化。

## 验收及边界

见[字体缓存 API](../font-cache-api.md)和[验收记录](../verification/font-cache.md)。覆盖默认实际启用、容量、内容变化、命中前预算、并发独占、自动过期、活跃租约、失败／取消恢复、流所有权及独立输出对照。有限回归不代表任意字体格式、强制抢占沙箱或长期无泄漏。
