# ADR-0118：显式配置一次的统一导出入口

- 状态：已采纳；2026-11-14 主题与 DOCX 字体语义修正的本地复验通过，已知限制见验收记录
- 日期：2026-11-13
- 修订：2026-11-14

## 背景

公式、源内容、字体缓存及 DOCX 能力已经位于库中，使用端仍要分别装配字体角色、公式文字字体、解析器、模板、布局引擎和 DOCX 字体槽／对象行距。重复装配容易遗漏配置，字体生命周期与不同目标的公式子集也容易相互影响。

## 决定

新建真实装配模块 `export4j-starter`，提供 `com.mirakyux.export4j.Export4j` 与 `FontFamily`。此模块在外围依赖既有组件、数学、模板和后端；核心、模型及布局不反向依赖它。应用仍可按需选择单独模块。starter 传递数学依赖，其许可和源码分发义务沿用原记录，不另复制上游实现。

初始化时声明实际字体来源、字体族名称、可选真实字重、全局主题及资源。相同声明用于正文物理字体、需要时的公式文字组和标准 Word 字体槽。PDF 使用显式物理字形且不合成缺失变体；DOCX 的普通正文和列表标记只保留文字、族与样式声明，不要求本地物理字体覆盖这些字形，也不按物理覆盖逐字改写 Word 字体槽。阅读端安装了哪些字体以及如何处理缺失字体或字形，由其所在系统决定。库不扫描系统字体、按名称查找文件、注册全局字体、自动下载资源或嵌入 DOCX 字体。HTML 已登记字体族保留各自角色，不合并为默认族；无法读取的字体来源和未登记角色继续明确失败。

业务入口为 `text`／`markdown`／`html`／正文 `xml`，目标为 PDF／DOCX 的路径或借用流。全局及请求 `ContentOptions` 保存声明意图。Markdown、HTML 和 XML 都保留主题独立的正文、六级标题、单元格与表格默认值；显式内容属性、XML 词法声明和 HTML CSS 按各自既有优先级覆盖，不用一份正文完整值抹平语义域差异。字符串不被猜测为文件、URL 或另一种源格式。

`ContentOptions.Resolved` 增加 `styles` 组件，由不可变 `SemanticStyles` 保存六级 `SemanticStyle` 与单元格文字外观。保留原 8／9 参数构造器及既有访问器，旧构造器维持历史均一样式语义。组件列表和参与值相等性的状态随之扩展；这不等于 record 反射、解构形状等结构协议完全不变，依赖这些协议的调用方需适配。

PDF 与 DOCX 分别调用数学模块的单目标投影。保持原双目标入口兼容，同时避免仅请求 PDF 时被不相关的 Word 原生公式子集拒绝。每次出现、来源预算和实际降级报告继续复用既有编译契约。默认严格且无降级候选；IMAGE／TEXT 必须明确声明，预算、取消和超时不能进入降级。

统一实例只保存可重开的字体来源和配置，默认拥有有界、空闲过期的缓存，或借用调用方缓存。每次操作按来源身份加载，并局部创建引擎／编译器；实际使用文字组时才准备公式文字快照，不永久保存已解析字体或文档。缓存不能使外部引用失效，也不触发 GC。实例可复用，请求和可变输入仍服从各自线程及执行边界。

路径输出先写同目录临时文件，执行范围最终检查成功后原子提交；不支持原子移动时失败，不采用静默非原子替换。流输出保持借用，失败可留下部分流。默认保留现有结构预算，不凭便捷入口虚构超时／输出字节上限；统一 `execution` 允许应用集中设置。

## 备选方案

- 在组件／核心模块直接依赖全部后端和适配器：破坏既有单向边界，未采用。
- 使用端各自编写公共包装器：继续重复资源和目标契约，未采用。
- 通过反射或类路径存在性静默启用可选模块：行为取决于环境，失败和依赖不可审阅，未采用。
- 内置系统字体扫描、自动降级或持有永久引擎：减少参数但改变字体、质量和生命周期契约，未采用。
- PDF 仍先执行双目标编译：不相关的 OMML 支持限制会阻止合法视觉导出，未采用。

## 验证与范围

样例和隔离消费者只使用统一公共入口，验证正文、中文公式文字、表格、图片、局部覆盖及同源 XML；结构检查与全页 PDF 双引擎／DOCX 独立阅读器验收另录。新增模块必须进入 BOM、POM、Gradle 元数据、源码／Javadoc、SBOM 和两路隔离消费，不以工作区类路径能运行代替分发验证。

本入口当前仅支持正文 XML；页区、分节和注释等没有被该投影完整覆盖的内容继续拒绝，不静默丢弃，也不扩展为一般 XML／Word 无损引擎。未支持的公式、字体、复杂脚本和目标布局仍遵循原 API 的子集。实际结果、工具和未执行项见[本批验收](../verification/easy-export.md)。
