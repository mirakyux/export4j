# ADR-0118：显式配置一次的统一导出入口

- 状态：已采纳；2026-11-14 主题与 DOCX 字体语义修正的本地复验通过，已知限制见验收记录
- 日期：2026-11-13
- 修订：2026-11-14、2026-11-20、2026-11-24

## 背景

公式、源内容、字体缓存及 DOCX 能力已经位于库中，使用端仍要分别装配字体角色、公式文字字体、解析器、模板、布局引擎和 DOCX 字体槽／对象行距。重复装配容易遗漏配置，字体生命周期与不同目标的公式子集也容易相互影响。

## 决定

新建真实装配模块 `export4j-starter`，提供 `com.mirakyux.export4j.Export4j` 与 `FontFamily`。此模块在外围依赖既有组件、数学、模板和后端；核心、模型及布局不反向依赖它。应用仍可按需选择单独模块。starter 传递数学依赖，其许可和源码分发义务沿用原记录，不另复制上游实现。

相同字体声明用于正文物理字体、需要时的公式文字组和标准 Word 字体槽。PDF 使用实际字形，缺失变体按字体角色和目标能力报错。DOCX 保留文字、族与样式声明，实际字体由阅读端解析。HTML 已登记字体族保留各自角色。无法读取的显式字体来源和未登记角色继续明确失败。

2026-11-24 增加无参 `Export4j.builder()`。该入口由 starter 在每次输出时检查固定系统路径，挑选已安装、格式受支持、嵌入许可有效的物理字体。字体集合按 PostScript 名称选成员。读取、解析及空闲释放沿用现有预算和实例缓存。使用已知路径的原因是减少启动配置，并将资源范围限制在可枚举的本地文件。显式字体入口、核心布局和其他后端入口继续由应用决定来源。默认字体随操作系统和已安装版本变化。

2026-11-20 收拢单次操作的字体绑定：一次按来源身份加载，形成不可变的默认栈、族／变体、业务角色及 Word 声明投影，由内容解析、PDF 引擎和 DOCX 适配器共同消费。`fontRole(name, family)` 提供稳定业务别名及 `_bold`／`_italic`／`_boldItalic` 真实变体；Java 默认值、XML 角色和 HTML 字体族使用同一登记。缺失变体明确失败，不合成、不按内部 `family_N` 顺序编写业务模板。新增业务族不自动改变默认缺字栈、公式文字默认栈或 Word 四脚本槽；默认及生成角色冲突、别名冲突在配置时拒绝。

业务入口为 `text`／`markdown`／`html`／`xml`，目标为 PDF／DOCX 的路径或借用流。全局及请求 `ContentOptions` 保存声明意图。Markdown、HTML 和 XML 都保留主题独立的正文、六级标题、单元格与表格默认值。显式内容属性、XML 词法声明和 HTML CSS 按各自优先级覆盖。字符串输入表示内容。

`ContentOptions.Resolved` 增加 `styles` 组件，由不可变 `SemanticStyles` 保存六级 `SemanticStyle` 与单元格文字外观。保留原 8／9 参数构造器及既有访问器，旧构造器维持历史均一样式语义。组件列表和参与值相等性的状态随之扩展；这不等于 record 反射、解构形状等结构协议完全不变，依赖这些协议的调用方需适配。

PDF 与 DOCX 分别调用数学模块的单目标投影。保持原双目标入口兼容，同时避免仅请求 PDF 时被不相关的 Word 原生公式子集拒绝。每次出现、来源预算和实际降级报告继续复用既有编译契约。默认严格且无降级候选；IMAGE／TEXT 必须明确声明，预算、取消和超时不能进入降级。

统一实例只保存可重开的字体来源和配置，默认拥有有界、空闲过期的缓存，或借用调用方缓存。每次操作按来源身份加载，并局部创建引擎／编译器；实际使用文字组时才准备公式文字快照，不永久保存已解析字体或文档。缓存不能使外部引用失效，也不触发 GC。实例可复用，请求和可变输入仍服从各自线程及执行边界。

统一入口可借用调用方配置的不可变 `PdfBackend`，使后端预算、临时流存储和 `PdfFontCache` 可达。每次输出仍创建独立 PDF 会话；关闭 exporter 不关闭调用方解析池，不跨文档共享 `PDFont` 或 COS 对象。核心模块不因该入口反向依赖后端。

XML 高频复用采用用户显式持有的 `XmlTemplate.Syntax`，由 `prepare`／`prepareXml` 保存纯字符串、来源位置、静态片段展开与预算计数。准备只验证安全 XML、根／片段结构及解析／展开限额，不建立内容会话、不加载字体或求公式。每次执行以当前主题、资源、解析器、数据快照和限额新建编译／绑定状态，并重新校验语义及原输入／解析／展开预算。计划不持有 `MathContentSource`、字体、资源或运行期 `DocumentTemplate`，不建立全局字符串缓存；准备时的片段展开不被执行编译器的同名片段替换。

路径输出先写同目录临时文件，执行范围最终检查成功后原子提交；不支持原子移动时失败，不采用静默非原子替换。流输出保持借用，失败可留下部分流。默认保留现有结构预算，不凭便捷入口虚构超时／输出字节上限；统一 `execution` 允许应用集中设置。

## 备选方案

- 在组件／核心模块直接依赖全部后端和适配器：破坏既有单向边界，未采用。
- 使用端各自编写公共包装器：继续重复资源和目标契约，未采用。
- 通过反射或类路径存在性静默启用可选模块：行为取决于环境，失败和依赖不可审阅，未采用。
- 递归扫描系统字体目录、自动降级或持有永久引擎会扩大文件访问、改变排版或延长资源寿命。采用固定候选和已有缓存。
- PDF 仍先执行双目标编译：不相关的 OMML 支持限制会阻止合法视觉导出，未采用。
- 全局缓存完整动态模板或永久操作 Session：可能持有单次数学解析器、字体及文档状态，且让资源和预算跨操作漂移；改用显式纯语法计划及单次不可变字体绑定。

## 验证与范围

样例和隔离消费者只使用统一公共入口，验证正文、中文公式文字、表格、图片、局部覆盖及同源 XML；结构检查与全页 PDF 双引擎／DOCX 独立阅读器验收另录。新增模块必须进入 BOM、POM、Gradle 元数据、源码／Javadoc、SBOM 和两路隔离消费，不以工作区类路径能运行代替分发验证。

XML 绑定完整分节和页区后按目标投影。PDF 支持脚注和尾注，DOCX 沿用原生目标对这些注释的拒绝规则。公式、字体、复杂脚本和目标布局仍遵循对应 API 的支持范围。实际结果见[本批验收](../verification/easy-export.md)。
