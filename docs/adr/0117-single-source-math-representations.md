# ADR-0117：一次源编译生成视觉公式与原生 Word 数学

- 状态：已采纳；实际验收另录
- 日期：2026-11-13

## 背景

相同源内容分别由消费方解析、转换和拟合会重复实现公式识别、表头锚点及降级规则。PDF 矢量可绘制不代表 Word 数学树可编辑；固定行距也可能裁切公式与原图。长期服务若永久持有引擎，缓存过期无法释放引擎中的字体引用。

## 决定

可选 `export4j-math` 提供不可变 `MathContent` 编写入口。一次受控 `ContentImporter` 编译产生视觉 `Document`、原生 `DocxMathDocument`、公式出现清单和逐目标表示变更。核心模型及后端仍不解释 TeX。XML 和 Java 模板通过同步回调复用同一解析器，数学模块不生产依赖模板模块。

每次出现具有本次编译私有的资源身份，不按 TeX 字符串去重。中间路径末尾的无绘制效果 MOVE 阻止模型值压缩合并相同公式；该段也计入预算。投影后视觉模型恢复实际轮廓，Word 槽有完整绑定。遗漏、重复、复制身份或改变逻辑文字／颜色明确失败；被动链接可以显式补充。不保留全局文档、公式出现或调用方回调。

视觉优先使用有界轮廓，Word 优先使用受支持的原生数学树。候选默认为空，严格失败；显式 IMAGE 从已验证轮廓生成等比 PNG，显式 TEXT 保留完整 TeX 和分隔符。每个目标独立记录发生位置、表示及原因，预算／取消／超时不能降级。实际字号与 RGB 随出现位置传入 Word，不能从中性占位符猜测局部样式。

几何检查使用真实容器宽度、物理列跨度和内边距；段落采用首行与后续行的较窄宽度，列表扣除层级缩进，连续分栏按最窄列预检。含公式的 Auto 列仍要求先确定宽度；无关 Auto 表不参与公式拟合。Word 最终度量和分页仍属于阅读软件，轮廓检查不能保证 Word 与 PDF 同页。

对象行框默认扩展，调用方可显式保留原固定行距。DOCX 独立提供多脚本字体声明与 `OBJECTS_AT_LEAST`，写出标准 OOXML 并严格读回；正文普通段落的既有 EXACT 默认不改变。表头使用可核查的物理格虚拟段落锚点，不为承载公式强制升级块单元格。

公式内文字使用可选 `MathTextFonts` 的显式编码字体快照。字体只在单次轮廓准备中解析，不注册全局字体、修改上游字体映射或搜索系统字体。配置自身的字节仍随配置存活；这与正文缓存的空闲释放是不同边界。

长期服务使用 `FontSource` 和 `DocumentEngineProvider` 保存来源配置，在同步操作内加载字体和创建引擎。provider 默认拥有有界缓存或显式借用外部缓存，不永久持有解析字体或引擎。调用方返回的布局、自行保留的引擎和编码字节配置仍可能持有资源，缓存不能使它们失效，也不触发 GC。

## 备选方案

- 消费方继续分别解析两种目标并修改 DOCX ZIP：重复来源与样式契约，未采用。
- 将所有公式固定转为 PNG：减少可编辑数学且隐藏支持差异，未采用。
- 给核心矢量增加 Word 或第三方公式句柄：破坏单向依赖，未采用。
- 按 TeX 文本或值相等资源认领：同式多次出现和用户自定义矢量会错误绑定，未采用。
- 全局字体注册／强制 GC：引入跨请求可变状态且不能保证资源回收，未采用。

## 验证与范围

回归覆盖混合标题／列表、重复表头、代码保护、相同公式多次出现、局部字号与颜色、缩进拟合、显式候选、提高总容量、取消及生命周期。公共入口必须另经本次本地制品的两类依赖解析、源内容完整性、PDF 双引擎及 DOCX 标准结构和独立渲染验收，见[富内容验收](../verification/rich-content.md)。

任意 LaTeX、宏、OCR 和一般跨格式无损仍不属于本决定。连续分栏／栅格的数学绑定保留语义容器，DOCX 未支持的布局继续明确拒绝；不为输出成功静默摊平。
