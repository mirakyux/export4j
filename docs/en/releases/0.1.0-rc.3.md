## Main changes

- `DocumentEngine` can hold immutable layout and component budget defaults. Ordinary export, paged export, block sources, replay, and target conversion inherit them. An explicit request override affects that request without changing a reusable engine or other requests. Dedicated long-table entry points retain their own budgets.
- Ordinary TrueType PDF text manages Unicode, CID, and actual GID separately, fixing source-text confusion when different Unicode characters share a glyph. Ordinary, paged, and spool paths retain source text and explicit advances. Exhausted character encodings allocate another font resource, and supplementary-plane characters retain complete mappings.
- New `InlineVector`/`VectorResource` types bind caller-generated bounded geometry and logical text into one indivisible object across body paragraphs, tables, fixed page regions, and streaming paths. Explicit resource registration can map HTML/Markdown image placeholders to vectors. Model editing, template evaluation, and replay retain the atomic binding between the object and its source.
- Eligible text-and-image lines retain native PDF text, improving extraction of Chinese table headings by ordinary extractors. A related fix distinguishes the source length of field/vector markers from expanded logical text, preventing later link offsets from drifting. Native output requires a safe whole line with undecorated LTR static TrueType text and exact codepoint-to-GID correspondence. Complex shaping and lines containing fields or vectors retain the outline path.
- Semantic tables containing only Fixed/Auto columns preserve the indivisible minimum width of inline images, fields, and vectors. Adjacent long text no longer squeezes an object below its width when a feasible allocation exists. Explicit maximum widths and page space must still accommodate the content; span constraints use their actual covered column intervals.
- Font loading, paragraph lookup, PDF glyph mapping, subsets, and spool resources use reuse with explicit limits and lifetimes. JDK physical-font loading reads the private `FontData` through an independent read-only cursor, avoiding an additional full byte clone before handing it to the JDK. Loading boundaries retain defensive copies without reducing document, formula, or image quality.
- The public documentation site provides Chinese/English guides, complete API sidebars, and language switching for the current page, with inline-vector and integration guides. The optional local designer remains outside Maven library/BOM publication.

## Other fixes

- Complete and paged layout accumulate semantic-source budgets across footnotes, body content, and endnotes. Component drawing accounts for cumulative work and responds to cancellation, preventing blocks or nesting from bypassing existing limits.
- DOCX path output uses a same-directory atomic replacement, preserving the old target on failure. Related input and conversion paths propagate cancellation and bounded reads. Borrowed streams remain caller-owned and may contain partial bytes after failure.
- PDF semantic recovery preserves reading order. List inference does not invent missing numbered parents: uncertain mixed indentation, level gaps, and zero markers retain their complete marker/text and report losses.
- Offline PDF trust validation can try alternative certificate chains, checking constraints and matching revocation evidence for each. Cycles, search, and evidence work share a finite budget and respond to cancellation. Validation does not read system trust stores or automatically access the network.
- Fixes align SVG miter limits and keep designer fonts, resource history, preview state, and table gestures consistent. Separate bounded designer request queues isolate uploads, cancellation, and static-resource requests.

## Compatibility and known limits

- Public APIs remain at release-candidate status. This RC3 build checked 741 accessible types against published RC2, finding zero incompatibilities, 28 additions, and zero leaked third-party types. Signature compatibility does not guarantee identical layout, extraction order, or rendering pixels.
- Headers still count toward source-row budgets: 10,000 body rows plus one header row require at least 10,001 source rows. Raising that allowance does not also raise text, drawing, resource, or output limits.
- The vector entry point does not parse arbitrary TeX, SVG, or MathML, or convert TeX↔OMML. PDF retains actual outlines and logical text through `ActualText`; extractors that ignore it are not guaranteed to recover the formula. DOCX/Web reject vectors by default. Only explicit `INLINE_VECTOR`/DEGRADE retains logical text and reports losses. XML v1 saving rejects vectors under every policy.
- Production still uses unmodified official PDFBox/FontBox 3.0.8, without embedded FontBox sources, custom duplicate classes, or an optional patch build. Internal font snapshots and parsing allocations remain; `close()` does not immediately reclaim heap data that other objects still reference.
- Cache limits and source-byte budgets are not heap or process-RSS limits. This literature acceptance batch did not remeasure allocations, time, heap, RSS, or capacity, and provides no fixed speedup, memory-halving, or general capacity guarantee.

## Existing local verification

This batch explicitly used version `0.1.0-rc.3` and completed `build`, `sbom`, `publishLocalBundle`, and production/capabilities/inlineVectors sample generation. Java test reports total 2,441 tests with zero failures, errors, or skips. Some tasks were restored from the Gradle build cache, so this count is not described as every test being executed again. The candidate documentation site's 407-page production build passed.

An OSV query on 2026-11-13 found no known advisory matches for the 13 third-party Java runtime dependencies in this batch's new SBOM. This is a result for those exact versions at that point in time, not a security guarantee. It does not cover unreported defects, native payloads, fonts, the JDK, or build tools.

The development-version integration batch completed the repository build, SBOM, local Maven bundle, and API checks. Separate consumers covered Gradle module metadata, POM-only Gradle resolution, and real isolated Maven resolution. Checks covered 16 libraries and the BOM. None of the 48 project binary/source/Javadoc JARs embedded FontBox, and each of the official FontBox's 192 classes had one provider. A temporary-key signing rehearsal covered 82 artifacts and tamper rejection; that test identity is not the formal publication signing identity.

The [independent vector sample](../../verification/inline-vectors.md) (Chinese) contains one page, three resources, and eight placements. Checks covered actual paths, baselines, atomic markers, PDFium searches/selections for original TeX, and full-page comparisons of two PDF renderers, SVG, and PNG. All five negative controls were rejected. This sample does not replace arbitrary-formula or real-literature acceptance.

[Two real articles](../../literature-pdf-integration.md#本次真实文献) (Chinese) total 17 pages, retaining 10 tables, 26 merged cells, 29 formula PNGs, and one original image. Those 29 formulas were not converted to vectors. Checks retained 27,077 stable character boxes and 3,416 source whitespace boundaries; three extractors recovered the targeted Chinese headings. Of 34 comparisons within Poppler/PDFium respectively, 32 had identical full-page pixels. Chinese page 2 has explicitly documented native-glyph differences, a corrected heading extraction order, and one faint pixel from an old space outline differing by at most four gray levels. All pages and differences were reviewed; the result is not described as identical pixels throughout both articles.

All 16 local RC3 library binary JARs are individually byte-identical to those used for the preceding 17-page acceptance batch, covering 2,151 ZIP entries and 1,287 classes. Its structure, extraction, and dual-renderer evidence is therefore reused; the articles are not described as newly regenerated for RC3 acceptance.

The new RC3 version passed isolated consumption through both Gradle module metadata and POM-only resolution. Each mode matched the SHA-256 of all 16 resolved library JARs to the local candidate artifacts, with all 17 project components (libraries and BOM) at `0.1.0-rc.3`. The new-API task compiled and ran `InlineVector` samples from those JARs, generating PDF/SVG/PNG. Independent checks of four PDFs across both modes covered actual paths, baselines, logical text, and link rectangles, with a maximum geometry error of approximately 0.00000125 pt. Comparisons using Poppler/PDFium, PNG, and resvg at 144 DPI passed.

Independent production acceptance passed. The capabilities sample used a temporary self-signed test certificate and passed actual OpenSSL signature verification and tamper rejection; this is not formal Maven publication signing. The release workflow now includes inlineVectors generation and independent verification, and isolated consumers include the new-API task. This configuration does not establish that the remote workflow has run.
